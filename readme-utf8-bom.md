# DIY M8 Headless — розробка з Codex

Портативний музичний трекер на офіційній прошивці Dirtywave M8 Headless, із фізичними кнопками, екраном і корпусом для 3D-друку.

**Статус:** технічне завдання та попередня архітектура. Залізо не зібране й не перевірене в межах цього репозиторію. BOM не є остаточним списком закупівлі.

## 1. Завдання для Codex

Допоможи довести проєкт від вибору готової DIY-реалізації до відтворюваної портативної збірки. Користувач має 3D-принтер, хоче зрозумілий BOM і покроковий супровід. Raspberry Pi Zero 2 W розглядається як кандидат; його наявність у користувача не підтверджена.

Працюй за документацією та кодом upstream-проєктів. Спочатку знайди й досліди придатні готові реалізації. Користувач наголосив, що існує репозиторій потрібного DIY-продукту, але точного посилання ще не надав. Не стверджуй, що знайдений кандидат — саме той проєкт, який він мав на увазі.

Веди документацію українською. Розділяй підтверджені факти, проєктні рішення та питання, що потребують перевірки на фізичному пристрої. Після кожного етапу фіксуй результат, перевірки й наступну конкретну дію.

Перед реалізацією:

1. Порівняй знайдені DIY-проєкти за доступністю BOM, схем, CAD, інструкцій і ліцензії.
2. Перевір наявність реалізації саме для Zero 2 W.
3. Обери відтворювану основу та поясни вибір у `docs/research.md`.
4. Зафіксуй URL, commit/tag, дату перегляду та обмеження джерел.
5. Не змішуй pinout, прошивку й конфігурацію різних збірок без явної перевірки.

## 3. Архітектура

| Вузол | Роль |
|---|---|
| Teensy 4.1 | Виконує офіційну прошивку M8 Headless: секвенсор, синтез, семпли |
| microSD у Teensy | Музичні проєкти, інструменти, семпли |
| Raspberry Pi Zero 2 W | Linux і m8c: інтерфейс, кнопки, маршрутизація аудіо |
| microSD у Pi | ОС, клієнт, конфігурація |
| USB Teensy → Pi | Передавання даних та USB-аудіо |
| Екран | Підключений до Pi; попередній вибір — HDMI |
| Кнопки | Підключені до GPIO Pi через програмний шар вводу |
| Аудіовихід | Вибрати й перевірити фізичний вихід для навушників/мікшера |
| Живлення | Спочатку зовнішні 5 В; батарея після вимірювання споживання |

**Teensy 4.1 обов'язковий для офіційної Headless-прошивки.** Teensy 4.0, Pi Zero 2 W, ESP32 або Pico не є прямою заміною для цього binary. Zero 2 W — кандидат на роль клієнта, продуктивність якого потрібно перевірити з конкретною ОС, екраном і версією m8c.

Здатність Teensy працювати з дисплеями чи аудіокодеками у власних програмах не доводить підтримку цих модулів закритою прошивкою M8. Не підключай довільні периферійні модулі до Teensy на підставі лише загальної специфікації.

## 4. Teensy 4.1: коротке знайомство

Мікроконтролерна плата, яка зазвичай виконує одну прошивку без Linux. Наведені нижче можливості належать платі загалом, а не автоматично всім функціям M8.

| Можливість | Характеристика | Практичний сенс |
|---|---|---|
| CPU | ARM Cortex-M7, 600 МГц | Синтез і обробка сигналів |
| Обчислення | FPU, DSP-інструкції | Фільтри, FFT, аудіоматематика |
| RAM | 1 МБ | Робочі дані й буфери |
| Flash | 8 МБ фізично; приблизно 7,75 МБ для програми | Зберігання прошивки |
| Розширення пам'яті | Місця під додаткові RAM/Flash | Не обов'язково для базового M8 |
| microSD | Вбудований слот SDIO | Окремий SD-модуль не потрібен |
| GPIO | 55 загалом, 42 на крайових рядах | Частина функцій ділить контакти |
| Аналогові входи | 18, 0–3,3 В | Потенціометри, датчики |
| PWM | 35 контактів | Керування зовнішніми драйверами та світлом |
| USB | Окремі Device і Host, до 480 Мбіт/с | Аудіо, MIDI, периферія за підтримки програми |
| Аудіоінтерфейси | I²S/TDM, S/PDIF | Потрібен зовнішній аналоговий тракт |
| UART / SPI / I²C | 8 / 3 / 3 | Зв'язок із периферією |
| CAN | 3, один із CAN FD | Потрібні зовнішні трансивери |
| Ethernet | 10/100 у відповідній комплектації | Потрібен комплект роз'єму |
| Wi-Fi / Bluetooth | Немає | У проєкті цю роль може виконувати Pi |
| Розробка | Arduino IDE + Teensy add-on, C/C++, PlatformIO | Власна програма замінює M8 на платі |
| Рівні GPIO | 3,3 В, не 5V-tolerant | Не подавати 5 В на сигнальні контакти |

## 5. Межі MVP

Перший результат — трекер, на якому можна створити патерн, відтворити його, зберегти проєкт і відкрити його після коректного вимкнення.

- Вісім основних кнопок: Up, Down, Left, Right, Shift, Play, Opt, Edit.
- Коректні одночасні натискання та утримання.
- Читабельний інтерфейс на компактному екрані.
- Стереозвук через фізичний вихід.
- Автозапуск клієнта та кнопка завершення роботи.
- Відтворюване встановлення із зафіксованими версіями.
- Розбірний корпус для 3D-друку.

Батарея — наступний етап. Аналоговий аудіовхід, DIN/TRS MIDI, динамік, енкодери, сенсорний інтерфейс і власна PCB — окремі розширення після стабільного MVP. Не обіцяти повну апаратну еквівалентність комерційному M8.

Zero 2 W має mini-HDMI; DSI-роз'єму немає. Не плутати HDMI, SPI, DPI та DSI-версії схожих екранів.

Фінальний BOM повинен містити: виробника, точний part number, кількість, інтерфейс, напругу, габарити, посилання на datasheet і продавця, ціну з валютою та датою, статус перевірки. Альтернативи вказувати лише з поясненням сумісності. Порахувати окремо мінімальний запуск, портативний MVP і батарейне доповнення; доставку враховувати окремо.

## 7. Електрика та аудіо

- Перед монтажем створити таблицю: фізичний контакт Pi, BCM-номер, сигнал, призначення, зайняті альтернативні функції.
- Для кнопок перевірити pull-up, debounce, події press/release та багатокнопкові комбінації. Не копіювати старі мапінги клавіш m8c без перевірки.
- Teensy для початкової перевірки живити через його USB. Не подавати паралельно зовнішнє живлення без перевірки VUSB/VIN і захисту від зворотного струму.
- Не додавати PCM5102 чи Teensy Audio Shield без перевірки сумісності обраного тракту. Лінійний DAC не слід автоматично вважати підсилювачем навушників.
- Задокументувати маршрут: Teensy USB Audio → програмний аудіошар → конкретний вихід.
- Для підключення до мікшера описати рівень сигналу й правильний кабель стерео → два канали.
- Перевірити затримку, випадіння, тріск і шум живлення. Фіксувати налаштування буфера, тривалість та умови тесту.

## 8. Живлення від батареї

Після вимірювання споживання вибрати захищений 1S Li-ion/LiPo акумулятор і модуль із заряджанням, підвищенням до 5 В, power-path та достатнім безперервним вихідним струмом. TP4056 сам по собі не забезпечує всі ці функції.

Коректне завершення Linux і фізичне відключення живлення — різні дії. Спроєктувати їх послідовність. Не вважати GPIO shutdown повним відключенням батареї.

Оцінка автономності: `години ≈ енергія батареї у Wh × ККД / середня потужність у W`. Не порівнювати mAh при різних напругах напряму. Остаточну автономність підтвердити вимірюванням. Перевірити перемикання зарядка/батарея без перезавантаження, нагрів і поведінку при низькому заряді.

## 9. Корпус для 3D-друку

Попередня концепція: вертикальний формат, екран зверху, кнопки під великими пальцями. Остаточні габарити визначаються обраними модулями й штекерами.

Вимоги:

- Знімна задня кришка на гвинтах; плати на стійках.
- Доступ до обох microSD, USB Teensy та кнопки програмування.
- Запас для штекерів, проводів і допустимого вигину шлейфів.
- Акумулятор не контактує з гострими ніжками й не затиснутий корпусом.
- Врахувати вентиляцію, антену Pi та положення перетворювача живлення.
- Окрема тестова панель кнопок і рамка екрана перед друком повного корпусу.
- Параметрична вихідна модель; STL для друку та STEP, якщо інструмент підтримує.
- Усі монтажні розміри підтвердити кресленнями виробника або вимірами користувача.

Якщо придатна модель уже існує, перевірити її ліцензію та сумісність. Не оголошувати CAD придатним до друку лише після успішного експорту: потрібні перевірка геометрії та фізична примірка.

## 12. Правила реалізації

- Перед змінами прочитай наявні файли та `AGENTS.md`, якщо він є.
- Спочатку завершуй корисну локальну роботу, потім проси дані, без яких наступна конкретна дія неможлива.
- Не запускай скрипти встановлення для Raspberry Pi на машині розробки. Додай перевірку платформи й архітектури.
- Скрипти мають повторно запускатися без дублювання конфігурації, створювати резервні копії змінених файлів і не приховувати помилки.
- Не форматуй носії та не прошивай підключені пристрої автоматично; користувач повинен явно визначити цільовий пристрій.
- Не підмінюй ARM-бінарник x86 AppImage. Перевіряй архітектуру та сумісність ОС.
- Зафіксуй сумісні commit/tag прошивки, клієнта та залежностей. Не використовуй рухомий `latest` у відтворюваній процедурі.
- Не вимагай root для самого клієнта, якщо достатньо груп і правил доступу.
- Не записуй у репозиторій Wi-Fi-паролі, ключі SSH та інші секрети.
- Не копіюй чужі binary, CAD або PCB для розповсюдження без перевірки ліцензії.
- Тести коду повинні перевіряти реальні ризики: release кнопок, комбінації, повторне встановлення. Апаратні припущення залишаються окремими перевірками.

## 13. Перше завдання після відкриття в Codex

Прочитай цей README та наявні файли. Досліди upstream-репозиторії, знайди придатний DIY-проєкт для Teensy 4.1 + Raspberry Pi Zero 2 W. Підготуй `docs/research.md` із порівнянням, `docs/bom.md` зі статусами деталей і `docs/decisions.md` із запропонованою основою. Вкажи, які файли корпусу й схеми реально доступні та які обмеження залишаються. Потім переходь до інструкції першого запуску Teensy на комп'ютері. До вибору конкретного дисплея та живлення не фіксуй pinout або габарити готового корпусу.
