# Покрокове складання

Згенеровано із src/data.js. Апаратна процедура не пройдена нами. Відкриті рішення й перевірки позначені в кожному етапі.

## 1. Обери свою збірку

Зрозумій, що робить кожна плата, і зафіксуй склад майбутнього інструмента.

1. **Розділи рушій та клієнт.** Teensy 4.1 запускає M8 Headless. Raspberry Pi 4 запускає клієнт дисплея й передає звук на USB-аудіоінтерфейс. У кожної плати власна microSD.

2. **Зафіксуй основу.** Основний клієнт — laamaa/m8c v2.2.3, клонований у upstream/m8c. Pi 4 — кандидат хоста за апаратним референсом RowdyVoyeur. Вигляд — Model:02. Pi Zero 2 W виключено.

3. **Відміть деталі, які вже є.** Відкрий BOM. Познач наявні компоненти, впиши реальні ціни у гривнях. Не купуй екран і кріплення, поки не звіриш габарити.

4. **Збери робоче місце.** Підготуй кардридер, USB data-кабель, мультиметр, ізольовану поверхню. Для механіки згодом знадобляться штангенциркуль і пробний друк.

**Зверни увагу:** Схожість із Model:02 — ціль дизайну. Габарити й апаратні функції оригіналу не гарантовані.

- [ ] Розумію ролі Teensy та Pi 4
- [ ] Перевірив наявні деталі в BOM
- [ ] Зберіг посилання і версії основи

Результат / наступна дія: План стендової збірки готовий. Наступна дія — підготувати карту для Teensy.

## 2. Підготуй дві microSD

Одна карта зберігає твої треки. Друга запускає Linux.

1. **Підпиши карти.** M8 / MUSIC для Teensy, PI / OS для Raspberry Pi. Це зменшує ризик записати образ Linux поверх музичних проєктів.

2. **Зроби резервну копію.** Якщо карта використовувалася, скопіюй файли. Перед форматуванням звір назву, ємність і цільовий диск у програмі.

3. **Підготуй карту M8.** Для обраної microSDHC 32 GB використовуй FAT32 та SD Memory Card Formatter за офіційною інструкцією. Після завершення перевір читання карти.

4. **Додай матеріал для перевірки.** Створи папку Samples і додай короткий WAV-файл. Безпечно витягни карту; встанови її в знеструмлений Teensy. Карту PI / OS поки відклади.

**Зверни увагу:** Форматування стирає файли. Посібник не форматує носії автоматично.

- [ ] Карти підписані й не переплутані
- [ ] Важливі файли скопійовані
- [ ] M8-карта читається та містить Samples

Результат / наступна дія: Карта M8 встановлена. Наступна дія — прошити Teensy.

[Першоджерело](https://github.com/Dirtywave/M8HeadlessFirmware/blob/e36808818bbd3c2530c2bb4bf3a1bd247ae7a0b4/README.md)

## 3. Дай Teensy голос

Встанови офіційний M8 Headless на Teensy 4.1 через TyUploader.

1. **Завантаж зафіксовані файли.** Відкрий посилання на M8_V4_0_2_HEADLESS.hex нижче. Завантаж raw-файл, а не HTML-сторінку. TyTools 0.9.9 візьми з релізу Koromix для своєї ОС.

2. **Обери саме цільовий Teensy.** Від’єднай інші Teensy/M8. Підключи плату напряму до комп’ютера USB data-кабелем. Відкрий TyUploader і перевір пристрій у списку.

3. **Запиши прошивку.** Натисни Upload, обери HEX і дочекайся завершення. Не відключай кабель під час запису. Очікувано пристрій визначиться як M8.

4. **Якщо пристрій не знайдено.** Перевір інший data-кабель і порт. Якщо потрібен bootloader, користуйся процедурою PJRC для кнопки Program. IHEX parse error часто означає, що завантажено HTML замість HEX.

**Зверни увагу:** Плата живиться через USB. Не підключай паралельно VIN і зовнішні 5 В без перевірки схеми живлення.

- [ ] У TyUploader обрано Teensy 4.1
- [ ] Прошивання завершилось без помилки
- [ ] Пристрій визначається як M8

Результат / наступна дія: Рушій готовий до тесту на ПК. Версія прошивки ще не є підтвердженням сумісності всієї збірки.

[Першоджерело](https://github.com/Dirtywave/M8Docs/blob/3886b348bc1b97818b25fa7348fc6a27775afc90/docs/M8HeadlessSetup.md)

## 4. Побач і почуй перший трек

Перевір екран, керування, звук і збереження до складання портативного пристрою.

1. **Запусти клієнт для своєї ОС.** З релізу laamaa/m8c v2.2.3 обери win64, macOS Apple Silicon/Intel або Linux x86_64. Розпакуй і запусти з під’єднаним Teensy. Це процедура для ПК, не ARM Pi.

2. **Перевір навігацію.** Стрілки переміщують курсор; z — Shift, x/Space — Play, a — Opt, s — Edit. Не вмикай Keyjazz під час перевірки цих клавіш.

3. **Перевір аудіо.** У m8c v2.2.3 відкрий F1, увімкни Audio enabled та Save; F12 перемикає звук. Вихід задається audio_device_name у секції [audio] config.ini або системним default. Закрий клієнт перед редагуванням файлу. Почни з низької гучності й не запускай паралельний loopback.

4. **Створи короткий приклад.** За посібником M8 створи Song → Chain → Phrase, додай інструмент і кілька нот. Відтвори та збережи пісню з унікальною назвою. Звір точні команди з мануалом своєї версії.

5. **Повтори після вимкнення.** Зупини відтворення, збережи, закрий клієнт і відключи Teensy. Підключи знову, відкрий збережену пісню. Запиши назву, версії та результат у журнал.

**Зверни увагу:** Скріншот нижче — справжній, але з історичного TouchDesigner. Його меню не слід шукати в m8c.

- [ ] Бачу інтерфейс і можу ним керувати
- [ ] Чую обидва канали без тріску
- [ ] Пісня відкрилася після повторного запуску

Результат / наступна дія: Базовий M8 пройшов твій стендовий тест. Наступна дія — перенести клієнт на Pi 4.

[Першоджерело](https://github.com/laamaa/m8c/blob/dbf61664f46c73c66552ace2ef71e8311d743125/README.md)

## 5. Перенеси M8 на Raspberry Pi 4

Підніми laamaa/m8c на ARM-хості, з готовим HDMI-екраном і USB-керуванням.

1. **Обери сумісний Linux-образ.** Для Pi 4 потрібен ARM-образ із графічною сесією, SDL3 та libserialport. Образ і пакети ще не зафіксовано — це відкрита перевірка. Перевір наявність libsdl3-dev у репозиторії ОС або збери SDL3 за його офіційним гайдом. Запиши версію та SHA-256 образу перед записом карти PI / OS.

2. **Підключи стенд.** На вимкненому Pi під’єднай micro-HDMI до екрана, USB-клавіатуру, Teensy та Ethernet. Встав карту ОС. Живлення Pi — через USB-C; дисплея — за його документацією.

3. **Заверши початкове налаштування.** Створи звичайного користувача, вистав локаль і аудіопристрій. Збережи мережу для діагностики. Перевір uname -m та /etc/os-release; не використовуй x86_64 AppImage на ARM.

4. **Збери оригінальний laamaa/m8c.** Встанови git, gcc, make, pkg-config та development-пакети SDL3/libserialport. Перевір pkg-config --modversion sdl3 libserialport. Команди нижче закріплюють source; доступність пакетів залежить від ОС.

5. **Запусти у відповідному графічному середовищі.** Запуск тільки через SSH може не мати доступу до дисплея. Пройди процедуру середовища upstream. Перевір fullscreen і читабельність. Не копіюй старі hdmi_* параметри без перевірки KMS/ОС.

```sh
git clone https://github.com/laamaa/m8c.git
cd m8c
git checkout --detach dbf61664f46c73c66552ace2ef71e8311d743125
pkg-config --modversion sdl3 libserialport
make
./m8c
```

**Зверни увагу:** Старий SDL2-fork і новий SDL3-клієнт — різні процедури. Повна збірка ОС/залежностей ще не перевірена нами на залізі.

- [ ] Записав назву образу та SHA-256
- [ ] Pi показує інтерфейс на HDMI
- [ ] Клієнт працює без root

Результат / наступна дія: Екран і USB-ввід працюють на Pi 4. Наступна дія — налаштувати звук.

[Першоджерело](https://github.com/laamaa/m8c/blob/dbf61664f46c73c66552ace2ef71e8311d743125/README.md)

## 6. Налаштуй чистий стереозвук

З’єднай Teensy USB Audio з фізичним виходом і проведи тривалий тест.

1. **Визнач пристрої.** Порівняй aplay -l і arecord -l до та після підключення. Запиши назву M8 capture й свого playback-пристрою, не покладайся на незмінність індексу card 1.

2. **Налаштуй маршрут m8c.** Через F1 увімкни Audio enabled і Save. Для конкретного виходу закрий клієнт і задай audio_device_name у [audio] config.ini; Default використовує системний вихід. Маршрут: Teensy USB Audio → m8c/SDL → USB-аудіо → навушники. F12 перемикає routing. Не вмикай одночасно зовнішній JACK/loopback.

3. **Перевір рівень і стерео.** На низькій гучності прослухай звук лише зліва, потім справа. Для мікшера використовуй кабель стерео TRS → два відповідні входи; один balanced mono-вхід не є стереовходом.

4. **Проведи 30-хвилинний тест.** Відтвори пісню з кількома семплами. Запиши sample rate, buffer, xruns, тріск, температуру і живлення. При випадіннях збільшуй буфер і повторюй ті самі умови.

```sh
aplay -l
arecord -l
vcgencmd measure_temp
vcgencmd get_throttled
```

**Зверни увагу:** Не під’єднуй I²S DAC напряму до Teensy за старим гайдом. Аналоговий вхід та MIDI не входять у цей MVP.

- [ ] Лівий і правий канали перевірено
- [ ] Параметри буфера записані
- [ ] 30 хвилин без випадінь і тріску

Результат / наступна дія: Аудіотракт перевірений у твоїй конфігурації. Наступна дія — фізичні кнопки.

## 7. Вісім кнопок. Увесь інструмент.

Повтори компонування Model:02 та перевір комбінації до монтажу панелі.

1. **Перевір контролер без пайки.** Для MVP використовуємо USB HID за референсом. На обраній макроклавіатурі перевір одночасне утримання Shift + Edit + стрілка. Контролер має надсилати key-up після відпускання.

2. **Признач команди.** Стрілки — навігація, z — Shift, x — Play, a — Opt, s — Edit. У браузерному тренажері можна перевірити клавіатуру; це не тест електрики майбутньої плати.

3. **Зроби тестову панель.** Приміряй один перемикач і ковпачок. Для підключення 8 кнопок потрібні схема конкретного HID-контролера та його напруга. До вибору плати паяльний pinout залишається відкритим.

4. **Перевір запуск і shutdown.** Після ручного тесту додай m8c до автозапуску графічної сесії обраної ОС, вказавши абсолютний шлях до binary. Спосіб залежить від desktop/session — старий Patchbox-модуль не переносимо. Збережи пісню і штатно заверши ОС; відключай живлення після halt.

5. **Перевір повторюваність.** Три холодні старти без клавіатури. Перевір усі кнопки, короткі/довгі натискання та відпускання в різному порядку. Віднови клавіатуру, якщо макроконтролер не дозволяє завершити ОС.

**Зверни увагу:** GPIO pinout із Zero-збірок не застосовується. Автозапуск не вмикай, поки ручний запуск і вихід не перевірені.

- [ ] Всі 8 кнопок та key-up працюють
- [ ] Комбінації не блокуються контролером
- [ ] 3 автозапуски й штатні вимкнення успішні

Результат / наступна дія: Керування готове до встановлення в корпус. Наступна дія — обміри й пробні деталі.

## 8. Збери свій корпус

Перевір об’єми, надрукуй пробні деталі, потім монтуй перевірений стенд.

1. **Зніми фактичні габарити.** Екран: PCB, активна область, отвори, роз’єми. Pi, Teensy, аудіо і HID: висота з компонентами та штекерами. Додай місце для кабелів і вентиляції.

2. **Переглянь 3D-компонування.** Розсунь шари в 3D-переглядачі. Це навчальна концепція за виглядом Model:02; кріплення та вирізи не відповідають ще не обраним модулям. Завантаж вихідний SCAD для адаптації.

3. **Надрукуй примірки.** Спочатку вікно дисплея й панель однієї кнопки. Перевір зазори, натискання й зняття ковпачків. Скоригуй модель за реальним друком, а не лише за nominal dimensions.

4. **Монтуй із вимкненим живленням.** Закріпи плати на стійках, ізолюй пайку, не притискай корпусом компоненти. Забезпеч доступ до обох SD і USB Teensy. Перевір відсутність короткого замикання перед подачею 5 В.

5. **Протестуй перед закриттям.** Запусти той самий аудіотест. Закрий кришку без зусилля, повтори тепловий тест. Якщо з’явились тріск, throttling чи пропуски кнопок — відкрий корпус і виправ причину.

**Зверни увагу:** STL-експорт концепції не означає готовність до друку. Повторювати оригінальні зовнішні розміри з Pi 4 без компонування не можна.

- [ ] Пробна панель і рамка приміряні
- [ ] Плати ізольовані, роз’єми доступні
- [ ] Закритий корпус пройшов тепловий тест

Результат / наступна дія: Стендовий MVP у власному корпусі. Наступна дія — виміряти споживання перед батареєю.

## 9. Зроби його портативним

Підбери живлення за виміряним навантаженням і перевір автономну роботу.

1. **Виміряй реальне навантаження.** Запиши середню та пікову потужність для завантаження, простою і важкої пісні. Врахуй дисплей та всі USB-модулі.

2. **Обери повний тракт живлення.** Потрібні узгоджені акумулятор, захист, заряджання, power-path і стабільні 5 В під піковим навантаженням. Звір datasheet, полярність, безперервний струм і теплові умови.

3. **Встанови акумулятор окремо від пайки.** Не затискай pouch-пакет, залиш місце на допустимі зміни розміру за документацією. Не клади його біля гарячих компонентів.

4. **Перевір переходи.** Під’єднай і від’єднай зарядку під час відтворення. Не повинно бути reboot чи випадіння аудіо. Перевір низький заряд, штатне завершення Linux і лише потім відключення живлення.

5. **Збережи паспорт збірки.** Запиши всі part numbers, образ ОС, commit, конфігурацію, автономність і температуру. Експортуй журнал посібника та зроби резервні копії обох карт.

**Зверни увагу:** Оцінка в калькуляторі — лише розрахунок. Остаточний час роботи визначає фізичний тест.

- [ ] Середня і пікова потужність виміряні
- [ ] Зарядка / батарея перемикаються без reboot
- [ ] Автономність виміряна, журнал збережено

Результат / наступна дія: Маєш задокументовану власну збірку. Збережи робочу конфігурацію перед наступними змінами.
